## Story
**As an** authenticated user,
**I want** to create a QR code by entering a text string and selecting encoding parameters,
**so that** I can generate and store a reproducible QR code for my AR/VR workflow.

## Acceptance Criteria
1. Create QR Code page is accessible from Dashboard and navigation
2. Form accepts a text string of up to 100 ASCII alphanumeric characters
3. User can select ECC level via dropdown (L, M, Q, H; default: M)
4. User can select QR version via dropdown (1–10; default: 5)
5. Optional Notes field is available for user annotation (max 300 characters)
6. Input is validated client-side and server-side:
   - String: required, max 100 chars, ASCII alphanumeric only
   - ECC: required, must be L/M/Q/H
   - Version: required, must be 1–10
7. If the string cannot be encoded with the selected ECC/version combination, a clear error message is shown
8. On successful validation, QR code is generated (preview displayed on page)
9. User can save QR code parameters to database (stored with UserId, timestamp)
10. After save, user is redirected to QR Code Details page or My QR Codes list
11. Anti-forgery token on POST form
12. QR code creation is logged

## Dev Notes
### Routes (from Architecture §3.6)
- GET /QRCodes/Create — Show form
- POST /QRCodes/Create — Submit new QR code (validates input, saves to DB)

### QR Code Generation
- Library: Net.Codecrete.QrCodeGenerator
- The library's API should be wrapped in a service (QRCodeService) for testability
- QR code images are generated on-the-fly, NOT stored in the database
- Only parameters are stored (DecodedText, ECC, Version) for reproducibility

### Input Constraints
- DecodedText: up to 100 ASCII alphanumeric characters (a-z, A-Z, 0-9)
- ECC Level: L (7%), M (15%), Q (25%), H (30%) error correction
- QR Version: 1–10 (determines matrix size; version 1 = 21×21, each version adds 4 modules)
- Notes: optional, max 300 characters
- Certain text/ECC/version combinations may exceed capacity — must validate and show error

### Wireframe (from Front-End Spec)
- Header + Navigation
- Form: Input String, Generate button → Preview, Store button, Download PDF button
- Inline feedback (success green, error red)

### Security
- [Authorize] on all actions
- Anti-forgery token
- Set UserId from HttpContext.User (never from form input)

### Testing
- Test creation with valid input → QR code saved, redirect to details
- Test creation with empty string → validation error
- Test creation with >100 chars → validation error
- Test creation with non-ASCII characters → validation error
- Test creation with incompatible ECC/version/text → encoding error message
- Test that UserId is set from authenticated user, not form
- Verify QR code appears in database after creation
