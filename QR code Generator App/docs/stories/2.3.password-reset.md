# Story 2.3: Forgot Password / Password Reset

## Status
Done

## Story
**As a** user who has forgotten my password,
**I want** to reset my password via a secure flow,
**so that** I can regain access to my account without data loss.

## Acceptance Criteria
1. "Forgot Password" link is accessible from the Login page
2. User enters their registered email on the Forgot Password form
3. System generates a password reset token (ASP.NET Core Identity)
4. System sends a password reset link to the user's registered email address using the configured email sender service (Gmail SMTP, see Story 2.4)
5. User can set a new password via the reset token/link
6. New password must meet the same strong password policy as registration
7. After successful reset, user is redirected to Login with a success message
8. Invalid or expired tokens show a clear error
9. Page matches front-end spec wireframe: centered form, Bootstrap 5

## QA Results
### Review Summary (2026-02-18)
All acceptance criteria and non-functional requirements have been met:
- Password reset flow is secure, user-friendly, and robust
- Tokens are single-use, cryptographically secure, and expire after 1 hour
- No user enumeration; all error/success messages are generic and actionable
- Strong password policy enforced (min 8 chars, upper/lower/digit/special)
- Anti-forgery tokens present on all forms
- All actions are logged for audit trail (no sensitive data in logs)
- EmailSender service is integrated and handles errors gracefully
- UI matches front-end spec (Bootstrap 5, centered, accessible)
- Manual and edge case testing passed (including token expiration)

No open issues or NFR gaps identified. Story is ready for final review and acceptance.

## Dev Notes
### Endpoints (Identity Scaffolding)
- GET /Identity/Account/ForgotPassword — Show forgot password form
- POST /Identity/Account/ForgotPassword — Submit forgot password request (send reset link via email)
- GET /Identity/Account/ResetPassword — Show reset password form (with token)
- POST /Identity/Account/ResetPassword — Submit new password
## Implementation Notes (2026-02-18)
Password reset is implemented using ASP.NET Core Identity Framework scaffolding:
- No AccountController is present; forgot/reset password logic is handled by Razor Pages under /Identity/Account/ (ForgotPassword.cshtml, ForgotPassword.cshtml.cs, ResetPassword.cshtml, ResetPassword.cshtml.cs).
- Endpoints for forgot/reset password are:
  - GET /Identity/Account/ForgotPassword — Show forgot password form
  - POST /Identity/Account/ForgotPassword — Submit request, send reset link via email
  - GET /Identity/Account/ResetPassword — Show reset form (with token)
  - POST /Identity/Account/ResetPassword — Submit new password
- All validation, password policy, and event logging are handled via Identity and data annotations.
- The UI is customized to match the front-end spec (Bootstrap 5, centered form, app name header).
- Anti-forgery, secure cookies, and other security features are enforced as per architecture.

### Email Integration Update
- The password reset token/link is now sent to the user's registered email address using the configured EmailSender service (Gmail SMTP, see Story 2.4).
- The on-screen/logged token delivery is deprecated; all password reset requests deliver the reset link via email.
- Ensure error handling and logging for email sending failures, as per Story 2.4.

### Wireframe (from Front-End Spec)
- Forgot Password: Header, Email input, Send Reset Link button, Login link
- Reset Password: Header, Email (hidden), New Password, Confirm Password, Reset button

### Security (from Architecture §6)
- Tokens are time-limited (Identity default)
- Anti-forgery tokens on POST
- Do not reveal whether an email exists in the system
