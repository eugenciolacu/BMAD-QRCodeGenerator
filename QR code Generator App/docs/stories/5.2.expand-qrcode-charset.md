# Story 5.2: Expand QR Code Character Set Support

## Status
Done

## Story
**As a** user,
**I want** to create QR codes with a broader character set including letters, digits, spaces, and email-safe symbols,
**so that** I can encode more types of information (URLs, emails, addresses with symbols, etc.) in my QR codes.

## Acceptance Criteria
1. ✅ QR code input accepts alphanumeric characters (a-z, A-Z, 0-9)
2. ✅ QR code input accepts space character
3. ✅ QR code input accepts common email-safe symbols: . , ; : ( ) ! @ # $ % & ' * + - / = ? ^ _ ` { | } ~
4. ✅ All printable ASCII characters are allowed (ASCII 32-126 range)
5. ✅ Max length remains 100 characters
6. ✅ Validation is consistent between client (view model) and server (service layer)
7. ✅ User receives appropriate error messages if input exceeds limits
8. ✅ Database can store all supported characters
9. ✅ QR code generation works correctly with all supported characters
10. ✅ Existing QR codes continue to work without modification

### Character Support Details
- **Validation Regex:** `[\x20-\x7E]` (all printable ASCII)
- **Character Range:** ASCII 32 (space) to ASCII 126 (tilde)
- **Includes:**
  - Alphanumeric: a-zA-Z0-9
  - Space: (space character)
  - Common symbols: . , ; : ( ) ! @ # $ % & ' * + - / = ? ^ _ ` { | } ~
  - And all other printable ASCII characters

### Before vs After
- **Before:** Only alphanumeric (a-z, A-Z, 0-9) — very restrictive
- **After:** All printable ASCII (letters, digits, space, symbols) — much more flexible
- **Validation:** Now consistent between client (view model) and server (service layer)
- **Regex Pattern:** Changed from `^[a-zA-Z0-9]{1,100}$` to `^[\x20-\x7E]{1,100}$`

### Supported Input Examples
- ✅ Single word: `hello`
- ✅ Multiple words: `hello world`
- ✅ Email format: `user@example.com`
- ✅ URL format: `https://example.com`
- ✅ Punctuated text: `Hello, World! How are you?`
- ✅ Special characters: `Price: $99.99 (50% off)`
- ✅ Mixed: `Test@123 with-symbols_and spaces!`

### Bug Fix: Regex Pattern Format Exception
**Issue:** FormatException when rendering Create page — "Input string was not in a correct format"
**Root Cause:** Curly braces `{1,100}` in regex pattern were interpreted as format string placeholders by ASP.NET MVC's client-side validation
**Solution:** Changed regex pattern from `[\x20-\x7E]{1,100}` to `[\x20-\x7E]+` and added separate length validation
**Result:** Same validation behavior, no format exceptions
