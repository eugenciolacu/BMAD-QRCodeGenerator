# Story 2.1: User Registration

## Status
Done

## Story
**As a** new user,
**I want** to register an account with my email and a strong password,
**so that** I can securely access the QR code management application.

## Acceptance Criteria
1. Registration page is accessible from the landing page via "Register" link
2. Registration form requires email and password (with confirmation)
3. Strong password policy is enforced (min 8 chars, uppercase, lowercase, digit, special char)
4. Email must be unique — duplicate email shows clear error
5. All inputs are validated client-side (HTML5 + unobtrusive JS) and server-side (model validation)
6. Validation errors are displayed inline with clear, user-friendly messages
7. Successful registration redirects user to the Login page (or Dashboard if auto-login)
8. Passwords are stored as salted hashes (Identity default)
9. Page matches front-end spec wireframe: centered form, Bootstrap 5 styling, app name header
10. Registration event is logged

## Implementation Notes (2026-02-17)
Registration is implemented using ASP.NET Core Identity Framework scaffolding:
- No AccountController is present; registration logic is handled by Razor Pages under /Identity/Account/ (Register.cshtml and Register.cshtml.cs).
- Endpoints for registration and login are:
  - GET /Identity/Account/Register — Show registration form
  - POST /Identity/Account/Register — Submit registration
  - GET /Identity/Account/Login — Show login form
- All validation, password policy, and event logging are handled via Identity and data annotations.
- The UI is customized to match the front-end spec (Bootstrap 5, centered form, app name header).
- Anti-forgery, secure cookies, and other security features are enforced as per architecture.
