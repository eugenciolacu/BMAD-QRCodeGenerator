# Story 1.2: Configure Database & EF Core Schema

## Status
Done

## Story
**As a** developer,
**I want** the SQL Server database configured with Entity Framework Core, including the ASP.NET Core Identity tables and the QR Codes table,
**so that** user and QR code data can be persisted and managed reliably.

## Acceptance Criteria
1. ApplicationDbContext class is created extending IdentityDbContext
2. QRCode entity model is defined with all required fields: Id (int, PK), UserId (string, FK → AspNetUsers.Id, NOT NULL), DecodedText (string, NOT NULL), ErrorCorrectionLevel (string, NOT NULL), QRVersion (int, NOT NULL), CreatedAt (DateTime, NOT NULL), Notes (string, nullable)
3. Foreign key relationship is configured: QRCode.UserId → AspNetUsers.Id with cascade delete
4. EF Core migration is created and can be applied via `dotnet ef database update`
5. Database is created with all Identity tables and QRCodes table
6. Seed data is not required (users self-register)
7. DbContext is registered in Program.cs with SQL Server provider

## Dev Notes
### Database Schema (from Architecture §3.5)
```
QRCodes table:
  Id          int         PK, NOT NULL, auto-increment
  UserId      string      FK → AspNetUsers.Id, NOT NULL
  DecodedText string      NOT NULL, max 100 chars
  ErrorCorrectionLevel string NOT NULL (L|M|Q|H)
  QRVersion   int         NOT NULL (1–10)
  CreatedAt   datetime    NOT NULL
  Notes       string      nullable
```

### ERD (from Architecture §3.5)
- AspNetUsers ||--o{ QRCodes : has (one user → many QR codes)
- QR codes are immutable (can only be created, read, or deleted — no edit)
