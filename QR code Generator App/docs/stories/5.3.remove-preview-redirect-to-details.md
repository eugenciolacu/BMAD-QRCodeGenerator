# Story 5.3: Remove Preview Functionality & Redirect to Details

## Status
Done

## Story
**As a** user,
**I want** to be redirected to the QR code details page after creating a QR code with a dynamic back button that takes me where I came from,
**so that** I can immediately view the complete details and navigate back intuitively without an unnecessary preview intermediate step.

## Acceptance Criteria
1. When a QR code is created and saved, the user is redirected to the Details page (not Create with previewId)
2. The redirect URL changes from `/QRCodes/Create?previewId=X` to `/QRCodes/Details/X`
3. The Details page displays all necessary QR code information and functionality
4. The preview parameter (previewId) is removed from the Create action
5. The Create view no longer displays the success message banner with preview
6. The Get handler for `Create(int? previewId)` no longer needs to process preview logic
7. User experience is improved by reducing navigation steps

## Dev Notes
### Implementation Summary

#### Changed Files
1. **QRCodesController.cs**
   - Modified `Create()` POST method: Changed redirect from `/QRCodes/Create?previewId={id}` to `/QRCodes/Details/{id}?returnTo=Create`
   - Updated `Details()` method to accept `string? returnTo` parameter
   - Pass `ReturnTo` property to view model based on the returnTo parameter (defaults to "Index")

2. **QRCodeDetailsViewModel.cs**
   - Added `ReturnTo` property (string) with default value "Index"
   - Stores where the user should return to: "Create" or "Index"

3. **Details.cshtml**
   - Updated back button to be dynamic based on `Model.ReturnTo`
   - Shows "Back to Create QR Code" if user came from Create action
   - Shows "Back to My QR Codes" if user came from Index or any other page

### User Flow
1. User creates a QR code → POST to Create
2. Redirect to Details with `returnTo=Create` parameter
3. Details page shows "Back to Create QR Code" button
4. Alternatively, if user navigates to Details from Index, button shows "Back to My QR Codes"

### Why This Change?
- Eliminates unnecessary preview page step
- Details page already has all required functionality (view, download, delete, navigate)
- Dynamic back button improves UX by returning to the context where user came from
- Simplifies controller logic by removing preview handling
