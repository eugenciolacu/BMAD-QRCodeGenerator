## 1. Security

| Concern | Implementation | Status | Notes |
|---------|----------------|--------|-------|
| Authentication enforcement | `[Authorize]` inherited from `QRCodesController` class level | ✅ Met | Unauthenticated GET to `/QRCodes/DownloadPdf/{id}` redirects to login; no PDF generated before auth check |
| IDOR prevention — ownership verification | `await _context.QRCodes.FirstOrDefaultAsync(q => q.Id == id && q.UserId == userId)` — single atomic query with both predicates | ✅ Met | Mitigates SEC-001; user cannot obtain another user's PDF by manipulating the ID parameter |
| UserId from authenticated context | `userId` resolved exclusively from `User.FindFirstValue(ClaimTypes.NameIdentifier)` — never from query string, route, or POST body | ✅ Met | Client cannot forge or supply a different `UserId`; parameter injection is ineffective |
| 404 for both non-existent and unauthorized IDs | Single `if (qrCode == null) return NotFound();` branch covers both cases identically | ✅ Met | Mitigates SEC-003; no information disclosure about record existence; identical response prevents timing oracle |
| No sensitive data in response headers | `File()` helper sets only `Content-Type` and `Content-Disposition`; no internal metadata leaked in headers | ✅ Met | PDF filename is `qrcode-{id}.pdf` — reveals only the numeric ID, which is already known to the owner |
| Content-Disposition: attachment enforced | `return File(pdfBytes, "application/pdf", $"qrcode-{id}.pdf")` — third argument causes `Content-Disposition: attachment` | ✅ Met | Browser downloads file; no inline rendering that could expose PDF content in browser history or tab |
| No path traversal risk | Filename constructed from integer `id` only: `$"qrcode-{id}.pdf"` — no user-supplied string in filename | ✅ Met | No directory traversal or file injection possible |
| Parameterised database queries | All DB access via EF Core LINQ (`FirstOrDefaultAsync` with lambda predicates) | ✅ Met | No SQL injection risk |
| Rate limiting | Global fixed-window limiter (10 req / 10 s) in `Program.cs` | ✅ Met | Baseline protection against PDF generation flood attacks |
| Secrets management | DB connection string in `appsettings.json` | ⚠️ Gap | Should use User Secrets (dev) or environment variable/Key Vault (prod). Pre-existing gap across all stories; not specific to PDF export. |

## 2. Performance

| Concern | Implementation | Status | Notes |
|---------|----------------|--------|-------|
| AC8: PDF generation < 1 second | `QRCodeService.GenerateImage()` is synchronous, in-memory; `PdfExportService.GeneratePdf()` calls `Document.Create(...).GeneratePdf()` — no I/O, no network, no database write | ✅ Met | Both operations are CPU-bound and sub-second for typical QR codes; see PERF-001 risk |
| No unnecessary database work | Single `FirstOrDefaultAsync` fetches entity; no second query; entity fields read directly in `PdfExportService` | ✅ Met | Minimal DB overhead in the PDF path |
| No file system I/O in PDF path | `Document.Create(...).GeneratePdf()` returns `byte[]` directly; no temp file written to disk | ✅ Met | No disk I/O latency; no disk space consumption |
| No caching needed | QuestPDF document generation is fast enough that caching would add complexity without proportional benefit | ✅ Met | Per-request generation satisfies AC2 (on-demand) and avoids stale-cache risk |
| Image first, then PDF | PNG image generated before PDF layout begins; image bytes passed as parameter — no double-generation | ✅ Met | Single pass through QRCodeService; image not regenerated inside PDF layout closure |
| Memory allocation | `GeneratePdf()` returns `byte[]`; allocated per-request within QuestPDF's internal memory stream; freed after response | ✅ Met | No static or shared buffers; GC can collect after response pipeline completes |
| PNG vs SVG for embedding | PNG chosen over raw SVG for PDF embedding — avoids SVG parser inconsistencies in QuestPDF (mitigates TECH-002) | ✅ Met | Trade-off: PNG is slightly larger than SVG but renders reliably across all PDF viewers |
| Overall response time | Expected < 500ms end-to-end (auth check + 1 DB query + PNG generation + QuestPDF layout) | ✅ Met | Well within AC8's 1-second threshold with margin |

## 3. Reliability

| Concern | Implementation | Status | Notes |
|---------|----------------|--------|-------|
| Image generation failure handled | `if (!success) return StatusCode(500, "Failed to generate QR code image.")` with `LogWarning` before PDF generation | ✅ Met | Controller never calls `GeneratePdf()` with an empty image; no blank-image PDF returned to user |
| QuestPDF license pre-registered | `QuestPDF.Settings.License = LicenseType.Community;` at top of `Program.cs` before `WebApplication.CreateBuilder()` | ✅ Met | Mitigates TECH-001; `QuestPdfException` cannot occur at runtime due to unregistered license |
| Framework-level input validation | `int id` route parameter is non-nullable; ASP.NET Core returns 400/404 for non-integer or missing IDs | ✅ Met | No null reference or format exception possible from route parameter |
| Null-safe metadata rendering | All four metadata fields guarded: `!string.IsNullOrEmpty(...)`, `qrCode.QRVersion > 0`, `qrCode.CreatedAt != default` → "N/A" fallback | ✅ Met | `GeneratePdf()` cannot throw on null/empty field values; mitigates DATA-001 |
| No resource leaks | `Document.Create(...).GeneratePdf()` manages its own `MemoryStream` internally; `byte[]` returned by value | ✅ Met | No `IDisposable` to forget; no `using` block required by caller |
| Log write failure | Serilog swallows internal log exceptions; PDF generation and response unaffected by logging failure | ✅ Met | Logging failure does not block the download |
| Unhandled `GeneratePdf()` exception | If QuestPDF throws an unexpected exception, ASP.NET Core's unhandled exception middleware returns 500 | ⚠️ Gap | No explicit `try/catch` around `_pdfExportService.GeneratePdf()`; unexpected QuestPDF exceptions yield a generic 500 page. Recommend wrapping with `LogError` and a user-friendly error response for production. |

## 7. Data Integrity & Privacy

| Concern | Implementation | Status | Notes |
|---------|----------------|--------|-------|
| QR code data read-only in this flow | `DownloadPdf` performs only a SELECT + in-memory PDF generation; no INSERT, UPDATE, or DELETE | ✅ Met | No risk of accidental data mutation during PDF export |
| No PDF stored in database | PDF bytes are returned directly to the client via `File()`; never persisted to DB or file system | ✅ Met | Matches AC2 and architecture §4.3 "not cached or stored"; no data retention concern |
| No PII in filename | Filename is `qrcode-{id}.pdf`; integer ID only; no user name, email, or content embedded | ✅ Met | Filename safe to appear in browser download history and file system |
| User data isolation | `UserId` ownership filter ensures users can only download their own QR code PDFs | ✅ Met | No cross-user data access possible |
| Metadata rendered from server-only data | All metadata in the PDF (`DecodedText`, `ECC`, `Version`, `CreatedAt`) comes from the database entity, never from client input | ✅ Met | No risk of client-supplied content injection into the PDF |
| Null-safe rendering prevents partial PDFs | "N/A" fallbacks ensure the PDF is always complete even if entity fields are unexpectedly empty | ✅ Met | User never receives a PDF with blank metadata rows |
| Privacy on ownership failure | Identical 404 for "not found" and "not owned" prevents enumeration of other users' QR code IDs | ✅ Met | Consistent with Details and DownloadImage actions |

## 10. Gaps & Recommendations Summary

| # | Severity | Concern | Recommendation |
|---|----------|---------|----------------|
| 1 | Medium | No `try/catch` around `_pdfExportService.GeneratePdf()` | Wrap PDF generation in `try/catch`; on exception log at `Error` level and return a user-friendly error (e.g., redirect with TempData error message: "Unable to generate PDF. Please try again."). Consistent gap with other stories. |
| 2 | Low | Generic 500 error page on PDF generation failure | Implement a user-friendly fallback: catch `QuestPdfException` specifically and redirect to Details page with error TempData message rather than showing the default exception page. |
| 3 | Low | Connection string in `appsettings.json` | Use ASP.NET Core User Secrets (dev) or environment variable/Key Vault (prod). Pre-existing gap across all stories; not specific to PDF export. |
| 4 | Minor | MIME type string `"application/pdf"` inline | Consider extracting to a named constant (e.g., `MediaTypeNames.Application.Pdf` from `System.Net.Mime`) for consistency with other controller return types if additional download formats are added in future. |
