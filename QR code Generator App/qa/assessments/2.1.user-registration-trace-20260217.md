# Traceability Matrix: Story 2.1 User Registration

Date: 2026-02-17
Reviewer: Quinn (Test Architect)

## Requirements to Test Mapping (Given-When-Then)

| Acceptance Criteria | Test Scenario ID(s)         | Given-When-Then Description                                                                 |
|--------------------|-----------------------------|---------------------------------------------------------------------------------------------|
| AC1                | 2.1-E2E-001                 | Given a user is on the landing page, When they click "Register", Then the registration page is shown |
| AC2                | 2.1-UNIT-001, 2.1-E2E-002   | Given the registration form, When email or password is missing, Then form submission is blocked and error shown |
| AC3                | 2.1-UNIT-002, 2.1-E2E-003   | Given a user enters a weak password, When submitting the form, Then an error is shown and registration is blocked |
| AC4                | 2.1-INT-001, 2.1-E2E-004    | Given an email is already registered, When submitting the form, Then a duplicate email error is shown |
| AC5                | 2.1-UNIT-003, 2.1-INT-002   | Given the registration form, When invalid data is entered, Then client and server validation errors are shown |
| AC6                | 2.1-E2E-005                 | Given invalid input, When submitting the form, Then inline error messages are displayed |
| AC7                | 2.1-INT-003                 | Given successful registration, When form is submitted, Then user is redirected to login/dashboard |
| AC8                | 2.1-INT-004                 | Given a new user registers, When password is stored, Then it is hashed and not in plain text |
| AC9                | 2.1-E2E-006                 | Given the registration page, When loaded, Then it matches the front-end wireframe and spec |
| AC10               | 2.1-INT-005                 | Given a registration event, When it occurs, Then it is written to the log for auditing |

## Notes
- All acceptance criteria are covered by at least one test scenario.
- Given-When-Then format ensures clear traceability from requirements to tests.
