## Core Four NFR Assessment

### 1. Security

| Check | Evidence | Status |
|-------|----------|--------|
| Authentication enforced | `[Authorize]` attribute on entire `QRCodesController` — unauthenticated users cannot access `/QRCodes/Details/{id}` | ✅ Pass |
| Ownership verification (data isolation) | `qrCode.UserId != userId` check before returning view; returns `NotFound()` to avoid revealing existence of other users' data | ✅ Pass |
| No sensitive data in logs | `LogInformation` logs only `UserId` and `QRCodeId` — no QR content, notes, or personal data logged | ✅ Pass |
| IDOR prevention | ID only accessible via authenticated, ownership-verified action; no direct object exposure | ✅ Pass |
| Anti-forgery on Delete | Delete button uses `@Html.AntiForgeryToken()` POST form — CSRF protected | ✅ Pass |
| No user-controlled input rendered unsanitized | Razor HTML-encodes all model properties by default (`@Model.DecodedText`, etc.) | ✅ Pass |

**Security verdict: PASS**

---

### 2. Performance

| Check | Evidence | Status |
|-------|----------|--------|
| Single DB call | `FindAsync(id)` — one primary-key lookup, no N+1 queries | ✅ Pass |
| QR regeneration cost | `GenerateSvg()` is a CPU-bound in-memory operation (no I/O); acceptable for single-record detail page | ✅ Pass |
| No unnecessary data loading | Only the single `QRCode` entity is fetched; no related collections loaded | ✅ Pass |
| Async DB access | `await _context.QRCodes.FindAsync(id)` — non-blocking | ✅ Pass |
| SVG rendered inline | Base64 data URI avoids a second HTTP request for the image | ✅ Pass |

**Performance verdict: PASS**

---

### 3. Reliability

| Check | Evidence | Status |
|-------|----------|--------|
| Null safety | Null check `qrCode == null` before accessing properties | ✅ Pass |
| QR generation failure handled | `success` flag checked; if false, `PreviewDataUri` is empty and view shows "Preview unavailable" | ✅ Pass |
| 404 for non-existent IDs | `return NotFound()` when `FindAsync` returns null | ✅ Pass |
| No unhandled exceptions in happy path | All branches covered: null entity, wrong owner, generation failure, success | ✅ Pass |
| Logging on access | `LogInformation` called for audit trail on every successful detail view | ✅ Pass |

**Reliability verdict: PASS**

### 4. Maintainability

| Check | Evidence | Status |
