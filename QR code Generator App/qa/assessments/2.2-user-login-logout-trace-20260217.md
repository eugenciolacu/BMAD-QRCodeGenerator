# Traceability Matrix: Story 2.2 User Login & Logout

Date: 2026-02-17
Reviewer: Quinn (Test Architect)

## Requirements to Test Mapping (Given-When-Then)

| Acceptance Criteria | Test Scenario ID(s)                     | Given-When-Then Description                                                                                               |
|--------------------|-----------------------------------------|---------------------------------------------------------------------------------------------------------------------------|
| AC1                | 2.2-E2E-001                             | Given a user is on the landing page, When they click "Login", Then the login page is shown                               |
| AC2                | 2.2-UNIT-001, 2.2-INT-001               | Given the login form, When email or password is missing, Then form submission is blocked and validation errors are shown |
| AC3                | 2.2-E2E-002                             | Given valid credentials, When the user submits the login form, Then they are redirected to the Dashboard                 |
| AC4                | 2.2-UNIT-002, 2.2-E2E-003               | Given invalid credentials, When the user attempts to log in, Then a generic "Invalid login attempt" error is shown       |
| AC5                | 2.2-UNIT-003, 2.2-INT-002               | Given the login form, When invalid data is entered, Then client-side and server-side validation errors are shown         |
| AC6                | 2.2-E2E-004, 2.2-INT-003                | Given an authenticated user, When they log out, Then the session/cookie is invalidated and they are redirected           |
| AC7                | 2.2-E2E-005                             | Given an authenticated user on any page, When viewing the navbar, Then the Logout option is visible                      |
| AC8                | 2.2-INT-004                             | Given failed login attempts, When authentication fails, Then an entry is written to the logs                             |
| AC9                | 2.2-INT-005                             | Given a period of inactivity, When the session timeout is reached, Then the user is logged out and must log in again     |
| AC10               | 2.2-E2E-006                             | Given the login page, When loaded, Then it matches the front-end wireframe (centered form, Bootstrap 5, links present)   |

## Notes
- All acceptance criteria are covered by at least one test scenario.
- Given-When-Then format ensures clear traceability from requirements to tests.
