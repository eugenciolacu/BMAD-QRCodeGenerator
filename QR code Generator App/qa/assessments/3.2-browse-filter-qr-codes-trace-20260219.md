## 3. Security Risk Traceability

| Risk ID | Risk Title | Mitigated By (Code) | Test Coverage |
|---------|-----------|---------------------|---------------|
| SEC-001 | UserId sourced from request (IDOR) | `currentUserId` always from `User.FindFirstValue(ClaimTypes.NameIdentifier)`; never from query string or form body | 3.2-INT-003, 3.2-E2E-002 |
| SEC-002 | Data leaked across users — missing tenant filter | `baseQuery` scoped to `userId` as the **first** `.Where()` before any further filter or pagination | 3.2-INT-004, 3.2-E2E-002 |
| SEC-003 | Count query / data query scoped differently (pagination metadata from wrong set) | Both `CountAsync()` (for `totalLibraryCount` and `totalCount`) and `ToListAsync()` operate on the same `filteredQuery` variable | 3.2-INT-008 |
| SEC-004 | Stored XSS via filter inputs reflected into HTML attributes | Filter values (`@Model.FilterContent` etc.) rendered via Razor auto-encoding; no `Html.Raw` used with user-supplied data | 3.2-INT-016 |
| SEC-005 | CSRF on delete — hidden form | Anti-forgery token in `<form id="delete-form">`; `[ValidateAntiForgeryToken]` enforced on Delete POST action (Story 3.4) | 3.2-INT-017 |
| PERF-001 | Unbounded page size via query string | `pageSize` hardcoded as `const int pageSize = 10`; never read from request | 3.2-INT-007 |
| TECH-001 | Out-of-range page number causes empty result or exception | `page = Math.Max(1, Math.Min(page, totalPages))` clamps to valid range after counting | 3.2-INT-007 |
| UX-001 | Single empty state conflates "no library" with "no filter match" | `IsEmptyLibrary` and `NoSearchResults` are independent boolean flags with separate view branches | 3.2-INT-013, 3.2-INT-014 |
| OPS-001 | No audit trail for list access | `_logger.LogInformation(...)` emits `UserId`, all active filter values, `Page`, `ResultCount` on every request | 3.2-INT-018 |

## 5. Deviations from Original Story

| # | Original Spec | Actual Implementation | Rationale |
|---|---------------|-----------------------|-----------|
| 1 | AC5: filter by DecodedText only | Per-column independent AND-chained filters: Content, ECC, Version, Notes, Created date range | Implemented at developer request; all filters are server-side; does not break any AC |
| 2 | AC3: content implied as truncated display | Text wraps in full (`word-break:break-word`) rather than hard-truncating | Requested by developer; improved UX; truncation properties retained in ViewModel for future use |
| 3 | AC6: sort by CreatedAt descending only | User-selectable sort by any column with ascending/descending direction; default remains CreatedAt descending | Enhancement requested by developer; does not compromise any AC |
| 4 | AC7: deselect behaviour not specified | Clicking the active row again deselects it and re-disables all action buttons | UX improvement requested by developer |
