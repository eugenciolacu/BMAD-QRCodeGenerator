# NFR Assessment: Story 2.4

Date: 2026-02-18
Reviewer: Quinn (Test Architect)

## Non-Functional Requirements (NFRs) Assessed

| NFR Category   | Scenario/Concern                                      | Assessment & Notes                                                                 |
|---------------|-------------------------------------------------------|-----------------------------------------------------------------------------------|
| Security      | Email credentials exposure                            | Credentials stored in appsettings.json; recommend using User Secrets or Key Vault. |
| Security      | Email confirmation link security                       | Uses ASP.NET Core Identity token; link is unique and time-limited.                |
| Reliability   | Email delivery reliability                            | Relies on Gmail SMTP; transient failures logged, but no retry logic.              |
| Performance   | Registration latency                                  | Email sending is async; registration not blocked by email delivery.               |
| Usability     | Error feedback to user                                | Errors logged; user receives generic error if email fails.                        |
| Maintainability| Configurability of email settings                     | All settings in appsettings.json; easy to update.                                 |
| Auditability  | Logging of email events                               | Success and failure events logged with details.                                   |
| Privacy       | User email stored, confirmation required               | Email not shared; confirmation required for activation.                           |
| Compliance    | GDPR/email best practices                             | No marketing emails; only transactional.                                          |

## Gaps & Recommendations
- Store sensitive credentials using User Secrets (dev) or Key Vault (prod)
- Consider adding retry logic for transient SMTP failures
- Optionally notify admin on repeated email send failures
- Periodically review logs for undelivered confirmation emails
- Document how to rotate/change email credentials securely

## NFR Coverage Summary
- Most NFRs are met for a typical registration email sender
- Security and reliability can be further improved with secrets management and retry logic
