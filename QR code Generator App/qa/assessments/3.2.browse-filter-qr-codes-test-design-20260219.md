### AC2: Page displays a table/grid of the current user's QR codes only

| ID          | Level       | Priority | Test Description                                                                                              | Justification                                              | Mitigates Risk |

## Coverage Validation Checklist

- [x] Every AC has at least one test scenario
- [x] AC9 (data isolation) cross-referenced to AC2 and pagination tests — no duplicate standalone scenarios created
- [x] All critical security risks (SEC-001, SEC-002, SEC-003, SEC-004) covered by P0 tests
- [x] P0 scenarios are Integration or Unit level (fast feedback loop)
- [x] E2E covers only critical user journeys and AC scenarios that cannot be verified at a lower level
- [x] TECH-002 accepted risk — explicitly noted in coverage matrix with no test assigned
- [x] Test IDs follow `{epic}.{story}-{LEVEL}-{SEQ}` convention

---

## Recommended Execution Order

1. **P0 Unit tests** — Fail fast on ViewModel shape and logic (3.2-UNIT-001 to 3.2-UNIT-006)
2. **P0 Integration tests** — Security and data isolation gates first (3.2-INT-002, INT-003, INT-004, INT-010, INT-011, INT-013, INT-015, INT-016)
3. **P1 Integration tests** — Core functionality (3.2-INT-001, INT-005, INT-006, INT-007, INT-009, INT-012, INT-014, INT-019)
4. **P1 E2E tests** — Critical user journeys (3.2-E2E-001 to 3.2-E2E-007, 3.2-E2E-010)
5. **P2 tests** — Logging, structural UI, edge cases (3.2-INT-008, INT-017, INT-018, UNIT-002, UNIT-003, UNIT-004, E2E-008, E2E-009)
