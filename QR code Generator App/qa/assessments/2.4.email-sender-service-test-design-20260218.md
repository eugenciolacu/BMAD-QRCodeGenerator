## Test Scenarios by Acceptance Criteria

### AC1: Implement a simple email sender service that can send emails via a configured Gmail account (SMTP).
#### Scenarios
| ID                 | Level       | Priority | Test                                               | Justification                  |
|--------------------|-------------|----------|----------------------------------------------------|-------------------------------|
| 2.4-UNIT-001       | Unit        | P0       | Validate SMTP config parsing                       | Pure logic, config validation  |
| 2.4-INT-001        | Integration | P0       | Send email via Gmail SMTP, expect success          | Core integration, critical     |
| 2.4-E2E-001        | E2E         | P1       | User triggers registration, receives email         | User journey, end-to-end       |

### AC2: Service must support sending emails for both registration confirmation and password reset flows.
#### Scenarios
| ID                 | Level       | Priority | Test                                               | Justification                  |
|--------------------|-------------|----------|----------------------------------------------------|-------------------------------|
| 2.4-UNIT-002       | Unit        | P1       | EmailSender handles both registration and reset    | Logic branch coverage          |
| 2.4-INT-002        | Integration | P1       | Registration triggers confirmation email           | Flow integration               |
| 2.4-INT-003        | Integration | P1       | Password reset triggers reset email                | Flow integration               |
| 2.4-E2E-002        | E2E         | P2       | User requests password reset, receives email       | User journey, end-to-end       |

### AC3: Update registration to require email confirmation (RequireConfirmedAccount = true)
#### Scenarios
| ID                 | Level       | Priority | Test                                               | Justification                  |
