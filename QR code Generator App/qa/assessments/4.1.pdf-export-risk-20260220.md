# Risk Profile: Story 4.1 — Download QR Code as PDF

Date: 2026-02-20
Reviewer: Quinn (Test Architect)

---

## Executive Summary

- **Total Risks Identified:** 10
- **Critical Risks (score 9):** 1
- **High Risks (score 6):** 3
- **Medium Risks (score 4):** 4
- **Low Risks (score 2):** 2
- **Overall Story Risk Score:** 47/100 *(Base 100 − 18 critical − 36 high − 20 medium − 4 low)*

The PDF Export story introduces a server-side file generation endpoint with meaningful security and performance exposure. The single critical risk is **unauthorized PDF download via IDOR** — a user manipulating the `{id}` parameter to obtain another user's QR code PDF. High-severity risks include missing `[Authorize]` protection, PDF generation latency exceeding the 1-second AC threshold, and a QuestPDF license/runtime misconfiguration that could break the feature entirely. The on-demand, stateless nature of PDF generation (no caching) means every request bears full compute cost, amplifying performance concerns under concurrent load.

---

## Critical Risks Requiring Immediate Attention

### 1. SEC-001: Ownership Not Verified Before PDF Generation — IDOR Vulnerability

**Score: 9 (Critical)**
**Probability:** High (3) — Without ownership verification, any authenticated user can request a PDF for any QR code ID and receive the document, including metadata belonging to another user
**Impact:** High (3) — Unauthorized disclosure of another user's QR code content, ECC level, version, and creation date; violation of data confidentiality and user trust

**Affected Components:** `QRCodesController (GET /QRCodes/DownloadPdf/{id})`, authorization logic

**Mitigation:**
- The download action **must** combine ownership and existence checks in a single query: `var qrCode = await _context.QRCodes.FirstOrDefaultAsync(q => q.Id == id && q.UserId == currentUserId);`
- Return `NotFound()` (404) for both non-existent IDs and records owned by another user — never reveal whether the ID exists
- **Never** call `FindAsync(id)` and then check ownership separately; the query must include both predicates atomically
- `currentUserId` must always be resolved from `HttpContext.User.FindFirstValue(ClaimTypes.NameIdentifier)`, never accepted from client input (query string, form field, route parameter)
- Code review checklist: confirm ownership filter is present in the EF Core query and cannot be bypassed

**Testing Focus:**
- Test: User A requests PDF for User B's QR code (valid ID, wrong owner) → 404 returned; no PDF generated
- Test: User A requests PDF for own QR code → valid PDF file returned with correct content
- Test: Request PDF for non-existent ID → 404 returned
- Test: Forged `UserId` in request headers/query string is ignored; only the authenticated session's user ID is used

## High Risks

### 2. SEC-002: Missing `[Authorize]` Attribute — Unauthenticated PDF Download

**Score: 6 (High)**
**Probability:** Medium (2) — If `[Authorize]` is omitted from the controller or the `DownloadPdf` action, anonymous requests could reach the endpoint and attempt PDF generation
**Impact:** High (3) — Unauthenticated access to a file generation endpoint; combined with SEC-001, this could expose any QR code as a PDF to any internet user

**Affected Components:** `QRCodesController`, action-level and class-level authorization attributes, `Program.cs` global auth policy

**Mitigation:**
- Apply `[Authorize]` at the controller class level to protect all actions by default
- Verify the global authentication policy in `Program.cs` is configured with `RequireAuthenticatedUser()` or equivalent fallback
- Integration test: unauthenticated GET to `/QRCodes/DownloadPdf/{id}` → 302 redirect to login page (or 401 if API), no PDF generated

**Testing Focus:**
- Test: No auth cookie, GET /QRCodes/DownloadPdf/{id} → redirect to login; no file returned
- Test: Expired session token → redirect or 401; no file returned
- Test: Authenticated user → request proceeds to ownership check

### 3. PERF-001: PDF Generation Exceeds 1-Second Acceptance Criterion

**Score: 6 (High)**
**Probability:** Medium (2) — QuestPDF with SVG rendering, metadata composition, and I/O can exceed 1 second under cold-start conditions, high server load, or with large QR SVG payloads
**Impact:** High (3) — AC 8 is directly violated; user-facing latency degrades experience; on-demand generation with no caching means every request pays the full cost

**Affected Components:** `PdfExportService.GeneratePdf()`, `QRCodeService` (image generation), QuestPDF rendering pipeline

**Mitigation:**
- Benchmark `PdfExportService.GeneratePdf()` in isolation during development (target < 500ms to leave headroom)
- Profile SVG embedding vs. PNG rasterisation — pre-rasterised PNG may be significantly faster to embed in QuestPDF than raw SVG
- Avoid synchronous blocking I/O inside the PDF generation pipeline; ensure `QRCodeService` image generation is awaitable
- Consider a pre-generated image byte array strategy: generate QR image once and pass to `PdfExportService`, not within the PDF layout closure
- Set a server-side generation timeout (e.g., 2 seconds) to fail gracefully rather than holding the thread indefinitely
- Document the performance baseline in test results for AC traceability

**Testing Focus:**
- Test (AC 8): Generate PDF for a typical QR code → total response time < 1 second (measure end-to-end at controller level)
- Load test: 10 concurrent PDF download requests → no requests exceed 2 seconds; no 500 errors
- Benchmark: `GeneratePdf()` unit test with stopwatch assertion (< 800ms target to allow controller overhead)

### 4. TECH-001: QuestPDF Community License Validation Failure — Runtime Breakage

**Score: 6 (High)**
**Probability:** Medium (2) — QuestPDF Community license requires explicit opt-in via `QuestPDF.Settings.License = LicenseType.Community` at app startup; omission causes a runtime exception on first PDF generation
**Impact:** High (3) — Feature is entirely non-functional; any attempt to generate a PDF throws `QuestPdfException`; no graceful degradation; users receive 500 errors

**Affected Components:** `Program.cs` (startup configuration), `PdfExportService`, QuestPDF NuGet package

**Mitigation:**
- Register the Community license at application startup before any PDF generation: `QuestPDF.Settings.License = LicenseType.Community;`
- Add a startup smoke test (health check or integration test) that calls `GeneratePdf()` with a minimal payload to confirm QuestPDF is operational immediately after deployment
- Document the license setting in code comments for future maintainers
- Validate the NuGet package version includes the Community license option (≥ 2022.12)

**Testing Focus:**
- Test: Application starts without license registration → verify `QuestPdfException` is thrown on first call (negative test)
- Test: Application starts with `LicenseType.Community` → PDF generation succeeds without exception
- Integration test: smoke-test PDF generation in CI pipeline to catch licensing regressions early

## Medium Risks

### 5. TECH-002: SVG Embedding Produces Blank or Corrupt QR Code in PDF

**Score: 4 (Medium)**
**Probability:** Low (1) — QuestPDF supports SVG natively, but third-party SVG output from the QR library may include unsupported constructs or namespace declarations that fail to render
**Impact:** High (3) — PDF is generated and downloaded successfully, but the QR code image is blank, malformed, or missing; the document appears valid but is functionally useless

**Affected Components:** `PdfExportService`, `QRCodeService` (SVG byte[] output), QuestPDF SVG rendering

**Mitigation:**
- Validate the SVG byte array from `QRCodeService` before passing to QuestPDF: check for non-empty, well-formed XML
- Test SVG embedding with the actual QR library output (not a hand-crafted SVG) in unit tests
- If SVG rendering is inconsistent, fall back to PNG rasterisation for PDF embedding: call a PNG-generating overload of `QRCodeService`
- Manually inspect a generated test PDF to confirm the QR code image is scannable

**Testing Focus:**
- Test: Generated PDF contains a non-blank QR code image at expected position
- Test: Open the PDF in a viewer and scan the QR code with a mobile device → original text is decoded correctly
- Test: `QRCodeService` returns valid SVG bytes; `GeneratePdf()` does not throw when consuming them

### 6. SEC-003: Information Disclosure via Differential Error Responses

**Score: 4 (Medium)**
**Probability:** Medium (2) — If the controller returns distinct error messages or status codes for "record not found" vs. "record found but not owned", an attacker can enumerate valid QR code IDs
**Impact:** Medium (2) — QR code existence is leaked for IDs the attacker does not own; enables targeted IDOR reconnaissance

**Affected Components:** `QRCodesController (GET /QRCodes/DownloadPdf/{id})`, error handling, HTTP response codes

**Mitigation:**
- Return identical 404 responses for both "not found" and "not owned" cases — no distinction in status code, response body, or timing
- Log the reason internally (audit trail) but never surface it in the HTTP response
- Review all error paths in the action method for any conditional logic that could reveal record existence

**Testing Focus:**
- Test: Request PDF for non-existent ID → 404 with generic message
- Test: Request PDF for valid ID owned by another user → identical 404 with identical message
- Test: Response times for the two cases should not differ significantly (timing oracle check)

### 7. AUD-001: PDF Download Events Not Logged — Insufficient Audit Trail

**Score: 4 (Medium)**
**Probability:** Medium (2) — If logging is omitted or captures insufficient detail, successful and failed download attempts cannot be traced in security incidents or user support cases
**Impact:** Medium (2) — No audit trail for PDF generation; cannot detect abuse patterns (e.g., user generating thousands of PDFs) or investigate reported incidents

**Affected Components:** `QRCodesController (GET /QRCodes/DownloadPdf/{id})`, `ILogger<QRCodesController>`, logging configuration

**Mitigation:**
- Log every successful PDF download: `_logger.LogInformation("User {UserId} downloaded PDF for QR code {QRCodeId} at {Timestamp}", currentUserId, id, DateTime.UtcNow);`
- Log failed/unauthorized attempts: `_logger.LogWarning("User {UserId} attempted to download PDF for QR code {QRCodeId} — not found or not owned", currentUserId, id);`
- Include: user ID, QR code ID, timestamp; optionally include Content-Length of returned PDF for debugging
- Ensure logs are persisted to durable storage; do not log sensitive QR code content

**Testing Focus:**
- Test: Successful PDF download → verify log entry contains user ID, QR code ID, timestamp
- Test: Unauthorized attempt → verify warning log entry with user ID and attempted QR code ID
- Review: Log entries must not contain raw QR code payload or other sensitive data

### 8. PERF-002: Memory Pressure from Concurrent On-Demand PDF Generation

**Score: 4 (Medium)**
**Probability:** Low (1) — Low risk under normal single-user or low-concurrency conditions; escalates if the app scales to many simultaneous users or is targeted by a download flood
**Impact:** High (3) — Each PDF generation holds large byte arrays in memory simultaneously; under concurrency, heap pressure may cause GC pauses, slow responses, or out-of-memory errors

**Affected Components:** `PdfExportService`, `MemoryStream` usage in QuestPDF pipeline, application memory

**Mitigation:**
- Use `MemoryStream` only within the scope of the request; dispose promptly after writing to response
- Do not accumulate multiple byte arrays per request; prefer streaming to the response directly if `QuestPDF` supports it
- Set reasonable application-level concurrency limits (e.g., via rate limiting middleware) to prevent PDF generation floods
- Monitor memory and GC metrics in production for anomalous spikes during PDF download activity

**Testing Focus:**
- Load test: 20 concurrent PDF download requests → no out-of-memory errors; memory returns to baseline after requests complete
- Test: `PdfExportService` disposes all streams and byte arrays after PDF is returned (no memory leaks verified via profiling in development)

## Low Risks

### 9. OPS-001: Incorrect HTTP Headers — PDF Opens in Browser Instead of Downloading

**Score: 2 (Low)**
**Probability:** Low (1) — Modern browsers may render PDFs inline rather than triggering a download if `Content-Disposition` or `Content-Type` headers are missing or incorrect
**Impact:** Medium (2) — Confusing user experience; user expects a file download but PDF opens in browser tab; AC 6 and AC 9 are violated

**Affected Components:** `QRCodesController (GET /QRCodes/DownloadPdf/{id})`, `FileContentResult`, response headers

**Mitigation:**
- Always return `File(pdfBytes, "application/pdf", $"qrcode-{id}.pdf")` — ASP.NET Core's `File()` helper sets both `Content-Type` and `Content-Disposition: attachment; filename="..."` automatically
- Verify the `Content-Disposition` header value in integration tests: must be `attachment`, not `inline`
- Test in multiple browsers (Chrome, Edge, Firefox) to confirm download is triggered correctly

**Testing Focus:**
- Test: HTTP response includes `Content-Type: application/pdf`
- Test: HTTP response includes `Content-Disposition: attachment; filename="qrcode-{id}.pdf"` with correct ID
- Manual test: clicking download button in each major browser triggers a Save dialog, not an inline render

---

### 10. DATA-001: PDF Metadata Reflects Stale or Incorrect QR Code Data

**Score: 2 (Low)**
**Probability:** Low (1) — QR codes are immutable (architecture §3.5); no update operations exist. However, if the PDF is generated from a partially-populated object (e.g., eager loading omitted), metadata fields may be null or default
**Impact:** Medium (2) — PDF contains blank or incorrect metadata fields (ECC Level, Version, Created Date); misleads the user and violates AC 4

**Affected Components:** `PdfExportService`, EF Core query in `QRCodesController` (ensure all required fields are loaded)

**Mitigation:**
- Ensure the EF Core query loads all fields required for PDF metadata: `DecodedText`, `ErrorCorrectionLevel`, `QRVersion`, `CreatedAt`; avoid `.Select()` projections that exclude these fields
- Validate that `GeneratePdf()` handles null or empty field values gracefully (e.g., display "N/A" rather than crashing)
- Include a PDF content assertion test to verify all four metadata fields appear with correct values

**Testing Focus:**
- Test: Generated PDF contains correct `DecodedText`, `ECC Level`, `QR Version`, and `Created Date` matching the database record
- Test: PDF metadata is not blank, defaulted, or null for any required field
- Test: Pass a `QRCode` object with null metadata fields to `GeneratePdf()` → method handles gracefully without exception

## Testing Recommendations

### Priority 1 (Critical Path)
- Ownership verification: User A cannot download User B's QR code as PDF (returns 404)
- Authorization: Unauthenticated users are redirected to login; no file generated
- QuestPDF Community license is registered at startup; no runtime exceptions

### Priority 2 (High Risk Mitigation)
- PDF generation time is < 1 second end-to-end under normal conditions (AC 8)
- Generate PDF for a known QR code; open in viewer; scan image → original text decoded correctly
- Negative test: QuestPDF called without license registration → exception thrown (confirms startup guard is needed)

### Priority 3 (Content & Headers)
- HTTP response headers confirm `Content-Type: application/pdf` and `Content-Disposition: attachment; filename="qrcode-{id}.pdf"`
- PDF contains all four metadata fields: DecodedText, ECC Level, QR Version, Created Date
- PDF download events (success and failure) appear in application logs with correct fields

### Priority 4 (Resilience & Load)
- Concurrent PDF generation (10–20 parallel requests) completes without errors or memory anomalies
- Stale-data and null-metadata edge cases handled gracefully without 500 errors
- Manual browser test: download triggers Save dialog in Chrome, Edge, and Firefox
