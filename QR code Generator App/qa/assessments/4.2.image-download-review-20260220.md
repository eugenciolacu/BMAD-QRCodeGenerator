# QA Review: 4.2.image-download.md

## Review Date
2026-02-20

## Summary
All acceptance criteria and non-functional requirements for the Image Download feature have been met. The implementation is secure, correct, and performant. Runtime log evidence confirms successful PNG downloads well within the 1-second performance target. All AC items are traceable to specific code and UI changes. No open issues or gaps identified.

## Acceptance Criteria Verification

| AC | Description | Status | Evidence |
|----|-------------|--------|----------|
| 1 | Download Image button on Details and My QR Codes pages | ✅ PASS | Format dropdown + button added to `Details.cshtml` card footer; Download Image button + format select added to `Index.cshtml` action bar |
| 2 | User can choose SVG or PNG via UI toggle | ✅ PASS | `<select>` dropdown on both pages; JS updates `href` on change; `?format=` query parameter passed correctly |
| 3 | Image generated on demand, not stored in database | ✅ PASS | `GenerateImage()` in `QRCodeService` is pure in-memory computation; no `_context.SaveChanges()` call in `DownloadImage` action |
| 4 | Meaningful filename (`qrcode-{id}.svg` / `qrcode-{id}.png`) | ✅ PASS | Controller: `var fileName = $"qrcode-{id}.{format.ToLower()}"` |
| 5 | Only owner can download; unauthorised returns 404 | ✅ PASS | Ownership check: `if (qrCode == null \|\| qrCode.UserId != userId) return NotFound();`; `[Authorize]` attribute on controller class |
| 6 | `Content-Disposition` header set for download | ✅ PASS | `return File(data, contentType, fileName)` — ASP.NET Core `FileContentResult` sets `Content-Disposition: attachment` automatically |
| 7 | Image generation under 1 second | ✅ PASS | Log evidence: PNG download `32?format=png` → 200 in **241ms** (first request, including JIT), **72ms** (warm). SVG is lightweight and faster. |

## Key Findings

- **Security:** Ownership is verified atomically using both `id` and `UserId`. The `[Authorize]` attribute prevents unauthenticated access at the controller level. The `format` parameter is sanitised server-side (only `svg`/`png` accepted; all else defaults to `svg`) — no path traversal or injection risk.
- **Performance:** Both PNG requests observed in application logs completed well under 1 second (241ms cold, 72ms warm), satisfying AC-7. Image generation uses in-memory buffer operations only.
- **SVG correctness:** Raw UTF-8 SVG bytes are returned with `Content-Type: image/svg+xml` — not a base64 data URI — which is appropriate for a file download.
- **PNG correctness:** BMP bytes from `QrCode.ToBmpBitmap()` are converted to PNG via `System.Drawing.Image.Save()` with `ImageFormat.Png`. The Windows-only `CA1416` platform warning is suppressed with a pragma and the constraint is documented.
- **UI:** Format selector on Details page wires the download link on both `onclick` and `onchange` events, ensuring the correct format is always sent. Same pattern applied to the Index page action bar.
- **Logging:** Successful downloads log `UserId`, `QRCodeId`, and `Format`. Failed generation attempts log at Warning level. No sensitive content in logs.
- **Build:** Project builds with 0 errors. Pre-existing `CS8601`/`CS8602` nullable warnings are unrelated to this story.

## Observations / Minor Notes

- SVG download is not explicitly visible in today's logs (only PNG was tested), but the code path is simpler and the same generation pipeline is exercised by `GenerateSvg()` throughout the app.
- The `System.Drawing.Common` Windows-only dependency is an accepted constraint for this project. If cross-platform support is needed in future, replace with a library such as `SkiaSharp` or `SixLabors.ImageSharp`.

## Recommendation

**PASS** — Story 4.2 is complete and ready for acceptance. All acceptance criteria are met, security controls are in place, performance is confirmed by log evidence, and the implementation is consistent with the project's architecture and coding standards.
