# Test Design: 2.3.password-reset.md

## Overview
This document outlines comprehensive test scenarios for the Password Reset feature as described in story 2.3.password-reset.md.

## Test Scenarios

### 1. Forgot Password Link
- Verify "Forgot Password" link is visible on the Login page
- Verify navigation to Forgot Password form

### 2. Email Submission
- Submit registered email: expect reset email sent
- Submit unregistered email: expect generic response (no user enumeration)
- Submit invalid email format: expect validation error

### 3. Token Generation & Email
- Verify reset token is generated and stored
- Verify reset email contains correct link and token
- Token is unique per request and expires as configured

### 4. Password Reset Form
- Access reset form with valid token: expect form loads
- Access with expired/invalid token: expect error message
- Fields: Email (readonly/hidden), New Password, Confirm Password
- Password and confirmation must match
- Password must meet policy (min length, complexity)

### 5. Reset Flow
- Complete reset with valid token: expect password updated, redirect to Login, success message
- Attempt reuse of token: expect failure
- Attempt reset with mismatched passwords: expect error

### 6. Security & Edge Cases
- Rate limit reset requests
- Ensure anti-forgery tokens present
- No sensitive data in logs
- Attempt reset for locked/deleted account: expect error

### 7. UI/UX
- Form matches front-end spec (centered, Bootstrap 5)
- All error/success messages are clear and actionable

## Regression Tests
- Existing login/registration flows are unaffected

## Non-Functional
- Email delivery time < 1 minute
- Reset flow works on all supported browsers/devices

## Traceability
Each scenario maps to acceptance criteria in story 2.3.password-reset.md.
