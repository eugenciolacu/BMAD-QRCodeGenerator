## 1. Security

| Concern | Implementation | Status | Notes |
|---------|---------------|--------|-------|
| Authentication enforcement | `[Authorize]` on entire `QRCodesController` | ✅ Met | Unauthenticated requests redirected to login; no action is accessible without auth |
| CSRF protection | `[ValidateAntiForgeryToken]` on POST + `@Html.AntiForgeryToken()` in form | ✅ Met | All state-changing requests require valid anti-forgery token |
| UserId injection prevention | No `UserId` in `CreateQRCodeViewModel`; always set from `User.FindFirstValue(ClaimTypes.NameIdentifier)` | ✅ Met | Mitigates SEC-001; attacker cannot forge ownership via POST body |
| Server-side input validation | `[Required]`, `[StringLength(100)]`, `[RegularExpression(@"^[a-zA-Z0-9]{1,100}$")]`; `ModelState.IsValid` gate; service-layer defence-in-depth regex | ✅ Met | Mitigates SEC-002, SEC-003; client-side bypass does not reach save logic |
| Stored XSS — Notes field | Razor auto-encodes all `@model` output; Notes rendered via `@code.Notes` (not `Html.Raw`) | ✅ Met | XSS payloads stored safely; not executable on render |
| Stored XSS — QR SVG | SVG encoded as `data:image/svg+xml;base64,...` and rendered in `<img src=...>` — not injected as raw HTML | ✅ Met | Eliminates SVG-based XSS vectors that `Html.Raw` would have introduced |
| IDOR on `previewId` | GET `Create(int? previewId)` checks `saved.UserId == userId` before populating ViewBag | ✅ Met | User cannot view another user's QR preview by guessing ID in query string |
| Rate limiting | Global fixed-window limiter (10 req / 10 s) configured in `Program.cs` | ✅ Met | Provides baseline DoS protection; no story-specific limiter needed for authenticated users |
| Parameterised queries | All DB access via EF Core (`_context.QRCodes.Find()`, `SaveChangesAsync()`) | ✅ Met | No SQL injection risk |
| Secrets management | DB connection string in `appsettings.json` / `appsettings.Development.json` | ⚠️ Gap | Connection string should use User Secrets (dev) or environment variable / Key Vault (prod). Low risk for on-premises deployment but recommended before production. |

## 2. Performance

| Concern | Implementation | Status | Notes |
|---------|---------------|--------|-------|
| QR generation latency | `QrCode.EncodeText()` + `ToSvgString(4)` + base64 encode — all in-process, no I/O | ✅ Met | Sub-millisecond for all valid inputs; no async needed for CPU-bound operation |
| Database write | Single `INSERT` via `SaveChangesAsync()` on a simple table with a covering index (`IX_QRCodes_UserId`) | ✅ Met | Expected < 5 ms on local SQL Server |
| Index page query | `WHERE UserId = @userId ORDER BY CreatedAt DESC` hits `IX_QRCodes_UserId` | ✅ Met | Efficient for a single user's dataset; no full-table scan |
| No pagination on Index | `QRCodes/Index` loads all user records with `.ToList()` | ⚠️ Gap | No pagination implemented yet. Acceptable for Story 3.1 (deferred to Story 3.2); could degrade for users with hundreds of records. |
| Preview regeneration | On redirect to `Create?previewId={id}`, SVG is regenerated from DB params (one `Find()` + in-process generation) | ✅ Met | Negligible overhead; avoids storing large blobs in TempData or DB |
| PNG download | Client-side JS canvas conversion — zero server load | ✅ Met | Server not involved in download |

## 3. Reliability

| Concern | Implementation | Status | Notes |
|---------|---------------|--------|-------|
| QR library exception isolation | `DataTooLongException` caught and returned as `(false, message)`; general `Exception` also caught | ✅ Met | Mitigates TECH-001; no unhandled 500 pages from encoding failures |
| Version-capacity mismatch | Explicit check `if (qr.Version > version)` before returning | ✅ Met | User-friendly error instead of silent wrong output |
| DB save failure | EF Core exceptions propagate to ASP.NET Core's unhandled exception middleware | ⚠️ Gap | No explicit try/catch around `SaveChangesAsync()`; a DB failure returns a 500 error to the user. Recommend wrapping in try/catch with a user-facing error message and log entry. |
| TempData cookie overflow | Replaced with `previewId` query string parameter | ✅ Met | Original bug (SVG > 4 KB cookie limit silently dropped) is resolved |
| Defensive input check in service | Service-layer regex check independent of model validation | ✅ Met | Data integrity held even if validation middleware is bypassed |

## 6. Auditability & Observability

| Concern | Implementation | Status | Notes |
|---------|---------------|--------|-------|
| Structured creation log | `LogInformation("QR code created. UserId={UserId} QRCodeId={QRCodeId} ECC={ECC} Version={Version}", ...)` | ✅ Met | Mitigates OPS-001; supports audit trail and debugging |

| Serilog configured | File + console sinks; reads from `appsettings.json` | ✅ Met | Log entries persist across restarts |
| No logging on GET | GET `Create` does not log on every page load | ✅ Met | Avoids log noise; only state changes are logged |

## 7. Data Integrity & Privacy

| Concern | Implementation | Status | Notes |
|---------|---------------|--------|-------|
| Ownership FK | `QRCodes.UserId` NOT NULL FK → `AspNetUsers.Id` CASCADE DELETE | ✅ Met | Orphaned records impossible; user deletion cleans up QR codes |
| DB constraints | `CK_QRCodes_ErrorCorrectionLevel` (IN 'L','M','Q','H') + `CK_QRCodes_QRVersion` (1–10) | ✅ Met | DB-level integrity even if application layer bypassed |
| Notes column length | `nvarchar(300)` via `HasMaxLength(300)` migration `AddQRCodesNotesMaxLength` | ✅ Met | Aligned with ViewModel `[StringLength(300)]` |
| QR image not stored | Only parameters stored; images generated on-demand | ✅ Met | Matches architecture spec; no blob storage needed |
| Data isolation | All queries filtered by `UserId`; no cross-user data access | ✅ Met | Users can only read/preview their own QR codes |
