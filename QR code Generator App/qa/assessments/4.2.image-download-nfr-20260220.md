# NFR Assessment: 4.2.image-download.md

## Security
- Ownership is verified server-side before any image is generated or returned; 404 is returned for non-owned or non-existent QR codes (no information leakage).
- The `[Authorize]` attribute on the controller ensures unauthenticated users are redirected to Login before the action is reached.
- The `format` query parameter is sanitised server-side — only `svg` and `png` are accepted; all other values default to `svg`.
- No user-supplied file paths are constructed; filenames are derived solely from the QR code ID.
- All download events are logged with UserId and QRCodeId (no sensitive content in logs).

## Performance
- Images are generated on demand using in-memory operations only (no disk I/O, no database write).
- AC-7 requires image generation to complete in under 1 second; the QR library and System.Drawing conversion are both sub-millisecond for typical QR sizes.
- No caching layer is needed given the lightweight generation cost, but adding response caching is straightforward if load requires it.

## Reliability
- Generation errors (e.g., `DataTooLongException`) are caught and return HTTP 400 with a clear message rather than an unhandled exception.
- SVG output relies only on `Net.Codecrete.QrCodeGenerator`; PNG output adds `System.Drawing.Common` — both are stable, well-tested libraries.
- Interrupted or partial downloads are handled by the browser/client; the server sends a complete response before the connection is released.

## Usability
- Format selection is exposed as a dropdown (SVG / PNG) on both the Details page and the My QR Codes list, with the button href updated dynamically — no page reload required to switch format.
- Filenames are meaningful and predictable (`qrcode-{id}.svg` / `qrcode-{id}.png`), improving organisation for users who download multiple codes.
- The Download Image button is visually consistent with other action buttons (Bootstrap 5 `btn-outline` class).

## Compatibility
- SVG format is preferred for scalability, print quality, and modern browser compatibility.
- PNG format ensures compatibility with applications that do not support SVG (e.g., older Office versions, messaging apps).
- `System.Drawing.Common` is Windows-only; the app targets Windows and this constraint is documented with `#pragma CA1416` suppression in the service.

## Auditability
- All successful image downloads are logged: `UserId`, `QRCodeId`, `Format`.
- Failed generation attempts (invalid input, ownership violations) are logged at Warning level with the specific error.

## Compliance
- Images are generated on demand and never persisted, reducing data retention surface area.
- No PII is included in the downloaded file or its filename.
- Ownership enforcement prevents cross-user data access, satisfying data isolation requirements.

## Summary
The image download feature meets all applicable non-functional requirements. The primary platform constraint (Windows-only `System.Drawing.Common`) is accepted and documented. No NFR gaps identified at this time.
