# Requirements Traceability Matrix: 2.3.password-reset.md

| Acceptance Criteria | Test Scenario (Given-When-Then) |
|--------------------|-----------------------------------|
| 1. "Forgot Password" link is accessible from the Login page | **Given** a user is on the Login page, **When** they view the page, **Then** a "Forgot Password" link is visible and navigates to the Forgot Password form |
| 2. User enters their registered email on the Forgot Password form | **Given** a user is on the Forgot Password page, **When** they enter a registered email and submit, **Then** the system processes the request and sends a reset link |
| 3. System generates a password reset token (ASP.NET Core Identity) | **Given** a valid email is submitted, **When** the request is processed, **Then** a secure password reset token is generated |
| 4. System sends a password reset link to the user's registered email address using the configured email sender service | **Given** a password reset token is generated, **When** the process completes, **Then** the user receives an email with a reset link |
| 5. User can set a new password via the reset token/link | **Given** a user clicks the reset link, **When** the Reset Password form loads, **Then** the user can enter and submit a new password |
| 6. New password must meet the same strong password policy as registration | **Given** a user enters a new password, **When** they submit the form, **Then** the password is validated against the policy and errors are shown if not met |
| 7. After successful reset, user is redirected to Login with a success message | **Given** a user successfully resets their password, **When** the process completes, **Then** they are redirected to the Login page with a success message |
| 8. Invalid or expired tokens show a clear error | **Given** a user accesses the Reset Password form with an invalid/expired token, **When** they submit, **Then** a clear error message is displayed |
| 9. Page matches front-end spec wireframe: centered form, Bootstrap 5 | **Given** a user views the Forgot or Reset Password pages, **When** the page loads, **Then** the layout and styling match the front-end spec |
