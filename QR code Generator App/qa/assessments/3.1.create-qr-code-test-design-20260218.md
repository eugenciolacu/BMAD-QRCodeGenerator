### AC2: Form accepts text string up to 100 ASCII alphanumeric characters

| ID             | Level | Priority | Test Description                                                  | Justification                    | Mitigates Risk |
|----------------|-------|----------|-------------------------------------------------------------------|----------------------------------|----------------|
| 3.1-UNIT-001   | Unit  | P0       | `DecodedText` = exactly 100 ASCII alphanumeric chars → valid      | Boundary value; pure model logic | SEC-002        |
| 3.1-UNIT-002   | Unit  | P0       | `DecodedText` = 101 chars → `StringLength` annotation fails       | Boundary value; pure model logic | SEC-002        |
| 3.1-UNIT-003   | Unit  | P0       | `DecodedText` = empty/null → `Required` annotation fails          | Required constraint               | SEC-002        |
| 3.1-UNIT-004   | Unit  | P0       | `DecodedText` = non-ASCII char (e.g., `é`, `中`, `<`) → regex fails | ASCII constraint; security       | SEC-002, SEC-003 |
| 3.1-UNIT-005   | Unit  | P0       | `DecodedText` = whitespace-only → regex fails                     | Edge case; whitespace not alphanumeric | SEC-003   |
| 3.1-UNIT-006   | Unit  | P0       | `DecodedText` = null byte / percent-encoded input → regex fails   | Injection edge case              | SEC-003        |

## Coverage Validation Checklist

- [x] Every AC has at least one test scenario
- [x] No duplicate coverage across test levels (AC11/INT-007 shared intentionally and noted)
- [x] All critical security risks (SEC-001, SEC-002) covered by P0 tests
- [x] All P0 scenarios are either Unit or Integration (fast feedback)

- [x] Test IDs follow `{epic}.{story}-{LEVEL}-{SEQ}` convention

## Recommended Execution Order

1. **P0 Unit tests** — Fail fast on model/validation logic (3.1-UNIT-001 to 3.1-UNIT-014)
2. **P0 Integration tests** — Security and data integrity (3.1-INT-002, 005–008, 011–013)
3. **P1 Integration tests** — Core functionality (3.1-INT-001, 003–004, 009–010, 014)
4. **P0/P1 E2E tests** — Critical user journeys (3.1-E2E-001 to 005)
5. **P2 tests** — Logging, architectural, UI detail (3.1-INT-015 to 017, 3.1-E2E-006–007)
6. **P3 tests** — Concurrency edge case (3.1-INT-018) as time permits
